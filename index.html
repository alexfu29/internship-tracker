Send queue

Ticking people opens a deck you work through one at a time — copy the message, open the compose window or profile, send it yourself, tick it off. All of that happens right here in the tracker, so nothing needs to be running for it to work.

Which signed-in Google account ✉ Open compose should use. With several signed in, 0 is whichever Google treats as primary — which is how a cold email goes out from the wrong address. Open Gmail on the account you want and read the number out of the URL.

The optional local agent does the same job in its own window, which outlives this tab. It is not set to start by itself — run the first command when you want it, the second when you're done.

Paste either command into PowerShell. Starting it opens no window — it runs quietly until you stop it or log out.

Drafts

Your own wording, kept here so you never leave the app to find it. Every 📋 Copy button fills one of these in and puts it on your clipboard. Nothing is ever sent for you.

Which draft you get is decided by the contact's channel and role, so you never have to pick: a LinkedIn contact gets the LinkedIn wording, anything else gets the email. The buttons say which one they'll hand you.

Each first message has a version per role. A BU Eng is someone you already share a school with, and a Field Eng is someone doing the work you want to do — different openings. Any other role — blank, or an older Hiring / VP Eng row — gets the plain version rather than being pushed into a bucket it never established. Follow-ups are one each, unchanged.

What fills in automatically:

{first}first name only — “Hi Sam,”
{name}their full name
{company}the company on the contact
{internship}the job you applied to, read off that company's row
{role}who they are — Hiring, VP Eng or BU Eng
{learn}“you” for a recruiter, “your work” for an engineer
{date}when you first contacted them
{days}days since your last contact or reminder
{channel}Email / LinkedIn / Other, as logged

{role} and {internship} are easy to mix up and are not the same thing — {role} is their job, {internship} is yours. Anything with no value on file comes through as a visible [company] so you spot the gap instead of sending a blank.

LinkedIn auto-populate

A browser can't read linkedin.com directly — LinkedIn refuses the request. So ⚡ Auto-populate can send the profile URL to a reader service, which returns the public, logged-out view. Only that public view — no login, no cookies, and nothing that touches your own LinkedIn account.

Leave this blank and no request is ever made. Pasting the copied profile page into the box works entirely on this device either way.

Find contacts

🔍 Find contacts on a company looks for Boston University alumni there, plus one engineer doing the work you want to do — then checks each one against their real profile before anything is saved. How many of each, and what counts as your field, are set below.

With an API key it searches for you. Leave the key blank and it copies the research prompt instead, for you to run in Claude and paste the reply back — same review step either way. The key is stored on this device only and goes nowhere except api.anthropic.com.

Free and local, if you'd rather. Every hosted search API refuses a browser — Brave and the public SearXNG instances send no CORS header, and Google's JSON API is closed to new signups. A SearXNG you run yourself has none of those problems: no key, no quota, and the query never leaves your machine. It also beats asking a model, because the profile links come out of a real search index and so can't be invented.

docker run -d -p 8888:8080 searxng/searxng, then in its settings.yml add json to search.formats and allow this page's origin. Put http://localhost:8888 below. It only works on the machine running it, so keep the API key for your phone.

Or use a hosted model to search. Paste a key for whichever you have — if you fill in only one, that's the one it uses and the choice below is ignored. Gemini's free tier is the cheaper way in; get a key at aistudio.google.com/apikey.

Used three ways, so they stay in step: the searches 🔎 Search runs, the check that a field pick's title actually bears it out, and the prompt you copy into Gemini.

Reminder timings

How long is too long is a judgement call, so it's yours. Blank or nonsense falls back to the default rather than producing a broken day count.

What 📋 Copy the research prompt hands you, and what the API is asked when a key is saved. Filled in for you: {company}, {roleLine}, and {bun} / {fieldn} / {fieldwords} from the counts and field terms above — so the prompt asks for exactly what 🔎 Search would have looked for.

AI research prompt

What the Copy AI prompt button sends. {companies} is replaced with your numbered list of companies you haven't applied to, including the role, link and note you saved for each, and {fieldwords} with the field terms above — the same ones the contact search uses, so the two never describe you differently.

Keep {companies} somewhere in the text. If you delete it the list gets appended at the end instead, so the prompt still works — but it reads better where you put it.
